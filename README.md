# GigaDict 1.0.10

GigaDict — фоновый клиент голосовой диктовки для Windows 11 x64. Пока удерживается глобальная горячая клавиша, приложение пишет микрофон в RAM; после отпускания отправляет PCM16/16 кГц локальному GigaSTT 2.21.0 и безопасно вставляет результат в исходное поле.

## Требования и сборка

- .NET 10 SDK (только для сборки);
- Windows 11 x64 для запуска и аппаратных тестов;
- локальный GigaSTT **2.21.0**, стандартный порт `9876`.

```powershell
dotnet restore GigaDict.slnx
dotnet test tests/GigaDict.Tests/GigaDict.Tests.csproj -c Release
dotnet publish src/GigaDict.App/GigaDict.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableWindowsTargeting=true -o artifacts/publish/win-x64
```

Запустите `artifacts\publish\win-x64\GigaDict.exe`. Администратор и установленный Runtime не нужны. После запуска приложение находится в системном трее; настройки хранятся отдельно в `%LOCALAPPDATA%\GigaDict\settings.json`.

## Использование

1. Откройте «Настройки» из трея и укажите `http://адрес-NAS:9876`.
2. Нажмите «Проверить соединение».
3. Выберите микрофон или устройство Windows по умолчанию.
4. Поместите курсор в редактируемое поле, удерживайте `F8`, говорите и отпустите `F8`.
5. `Esc` во время записи отменяет только текущую диктовку.
6. «Автоматические пробелы» в настройках добавляют пробел между вставкой и соседним словом, если редактор сообщает символы рядом с курсором через UI Automation; иначе текст вставляется как есть.

Записи идут через FIFO с одним запросом к NAS. Следующую запись можно начать, пока обрабатывается предыдущая. По умолчанию очередь содержит до 10 заданий, общий PCM-лимит — 128 МиБ, длительность — 300 секунд. Аудио и история никогда не сохраняются на диск; история последних десяти результатов существует только до завершения процесса.

В строгом режиме автовставка выполняется, только если UI Automation смогла надёжно определить редактируемый элемент и фокус ни разу не менялся. Совместимый режим разрешает редакторы Firefox/WebView2, если активными остались то же окно и тот же процесс; распознанные поля пароля по-прежнему блокируются. В обоих режимах любое полученное событие смены фокуса, активного окна или рабочего стола запрещает вставку для уже начатых диктовок, даже после возврата в исходное поле. При недоступном отслеживании фокуса вставка также запрещена. Текст остаётся в RAM-истории и доступен для ручного копирования. По умолчанию используются строгая защита и Unicode `SendInput`; совместимая защита и Clipboard + Ctrl+V включаются вручную.

Лимиты очереди и PCM-памяти применяются после сохранения настроек без перезапуска. Уменьшение лимита сохраняет принятые задания, но блокирует новые до освобождения места. Текущая запись сохраняет настройки, действовавшие при её начале.

Серверные endpoint и протокол реализованы по документации [GigaSTT v2.21.0](https://github.com/ekhodzitsky/gigastt/blob/v2.21.0/docs/api.md): `POST /v1/transcribe`, `GET /ready` и PCM16 mono 16000 Гц. WebSocket `/v1/ws` намеренно не используется: для диктовки по отпусканию клавиши он не даёт преимуществ перед REST.

## GigaSTT в Docker

Готовый необязательный deployment-пакет для NAS находится в [`deploy/gigastt`](deploy/gigastt/README.md). Он закрепляет CPU-образ GigaSTT `2.22.0`, модель `e2e_rnnt`, один inference-слот и постоянный volume для модели. По умолчанию порт доступен только на loopback NAS; для Windows-клиента укажите LAN-IP NAS в локальном `.env`.
