# Архитектура

Решение состоит из шести проектов:

- `GigaDict.Core` — настройки, снимок задачи, явная машина состояний, FIFO, лимиты RAM, история и логика границ текста.
- `GigaDict.Audio` — WASAPI shared mode через NAudio, RAM-буфер, downmix и WDL-ресемплинг в PCM16 mono 16000 Гц.
- `GigaDict.Recognition` — HTTP, WebSocket protocol 1.0 и ограниченные повторы.
- `GigaDict.Input` — `WH_KEYBOARD_LL`, WinEvent focus hook, UI Automation COM, `SendInput` и Clipboard.
- `GigaDict.App` — WinForms, `NotifyIcon`, настройки, single-instance, автозапуск и координация.
- `GigaDict.Tests` — платформонезависимые unit/transport tests.

## Потоки данных

Keyboard hook выполняет только обновление маленькой state machine и постановку события в последовательную очередь команд. Один consumer дожидается завершения каждой команды, включая асинхронную остановку захвата, перед следующей. Отдельные клавиши неполной комбинации и модификаторы обычных сочетаний не подавляются; для подавленных нажатий подавляются и отпускания. WASAPI callback копирует очередной блок в ограниченный RAM-буфер и при достижении лимита ставит команду остановки в ту же очередь. После отпускания клавиши преобразование аудио выполняется вне callback. Каждая запись фиксирует настройки и привязку фокуса при запуске и сохраняет их до завершения захвата.

Перед освобождением захват отсоединяется под блокировкой; ожидание его потока и ресемплинг выполняются после снятия блокировки. Callback сверяет отправителя с текущим захватом, чтобы события предыдущей записи не затронули следующую. Ошибка захвата передаётся ожидающему остановки коду, а частичное аудио не считается успешной записью.

Один worker последовательно вызывает выбранный транспорт. Отдельный channel вставки получает результаты, поэтому ожидание отпускания следующей горячей клавиши не занимает worker распознавания. Каждая задача сохраняет собственные настройки и собственный `FocusIdentity`.

Переход задания в `Queued` и учёт PCM-памяти выполняются до публикации в channel. Лимиты приёма и истории изменяются под общей блокировкой без замены worker; уже принятые задания сохраняются. Ошибка или отмена передачи распознанного результата оставляет текст в RAM-истории и запрещает автовставку.

## Безопасность вставки

В начале записи фиксируются HWND, PID и UI Automation Runtime ID. WinEvent hooks для `EVENT_OBJECT_FOCUS`, `EVENT_SYSTEM_FOREGROUND` и `EVENT_SYSTEM_DESKTOPSWITCH` действуют на протяжении жизни задания. Callback за постоянное время увеличивает поколение фокуса, необратимо запрещая вставку для уже отслеживаемых заданий в обоих режимах. UI Automation в callback не вызывается. Если любой hook не установлен, захват безопасной идентичности запрещён. Перед вставкой идентичность проверяется снова, а при Unicode-вводе — между блоками символов. В строгом режиме неизвестные, password, disabled и не-Edit/Document элементы запрещены. Фокус никогда не восстанавливается программно.

Clipboard-вставка сообщает об ошибке при потере фокуса и восстанавливает предыдущий буфер в `finally`, в том числе при отмене или ошибке `SendInput`. Восстановление выполняется только при сохранении собственного marker; исходно пустой буфер очищается.

Собственные события `SendInput` имеют `dwExtraInfo` marker и игнорируются hook. Повторная сетевая попытка помечает результат и запрещает запоздалую автовставку.

## Память и завершение

Аудио существует только как массивы в памяти. HTTP-запрос потоково добавляет WAV-заголовок без второго полного WAV-буфера; WebSocket передаёт PCM блоками. После распознавания/ошибки/отмены массив очищается. Настройки сохраняются через временный файл и атомарное переименование; распознанный текст в них не попадает.
